# v0.1.0 — Bootstrap

## Ziel

Ein deploybarer Prozess, der startet, `/health` beantwortet und sauber
herunterfährt. Noch kein Discord, noch kein Feature — aber die komplette
Kette von `uv sync` bis Deploy auf Fuchs funktioniert.

## Voraussetzungen

- Runner auf Fuchs registriert und aktiv (`docs/deployment/runner.md`)
- Repo-Variablen `DEPLOY_DIR` und `APP_PORT` gesetzt
- `ARCHITECTURE.md` deckt sich mit dem Verzeichnisbaum

## Umfang

### Projekt-Setup

- `pyproject.toml`: uv, Python 3.12, Dependency-Gruppen `dev`, Script-Entry
  `teabot`, Ruff-Konfiguration (Zeilenlänge 100), Mypy-Konfiguration (strict
  für `src/`), pytest-Konfiguration
- `uv.lock` erzeugt und committet
- `.gitignore`: Python, uv, `data/`, `.env`, Coverage, IDE

### Konfiguration

- `config.py` mit pydantic-settings: alle Pflichtwerte ohne Default, damit ein
  fehlender Wert beim Start scheitert
- `.env.example` mit allen Schlüsseln, kommentiert, ohne echte Werte

### Datenbank

- `db/engine.py`: Async-Engine, PRAGMA-Hook (`WAL`, `foreign_keys=ON`,
  `busy_timeout`, `synchronous=NORMAL`)
- `db/session.py`: `session_scope()`, Dependency `get_db`
- `db/base.py`: Declarative Base mit Naming Convention für Constraints
- `db/mixins.py`: `id`, `created_at`, `updated_at` (UTC, timezone-aware),
  `GuildScopedMixin`
- Alembic initialisiert, `env.py` mit Modul-Discovery, eine Baseline-Migration

### Registry

- `core/registry.py`: Discovery über `pkgutil`, sammelt `MODULE`, `router`,
  `Cog`, `SETTINGS`, `PERMISSIONS`
- `core/exceptions/`: `base.py`, `access.py`, `data.py`, `bot.py`, `config.py`
- `modules/health/`: Minimalmodul mit `MODULE` und `router`, liefert `/health`
  — dient als Prüfstein für die Registry

### Composition Root

- `main.py`, `src/teabot/teabot.py`, `app/` gemäß `ARCHITECTURE.md` §10
- Lifespan vorhanden, Bot-Start noch als Platzhalter
- Logging-Baum konfiguriert, `discord`-Logger auf `WARNING` gedeckelt
- Exception-Handler in `app/`, die Domain-Exceptions auf HTTP-Status mappen
- `__init__.py` in allen Unterpaketen

### Tests

- `tests/conftest.py`: In-Memory-Engine mit produktionsgleichen PRAGMAs,
  Session-Fixture, App-Client über `httpx.AsyncClient`
- Test: `/health` antwortet 200
- Test: Registry findet das `health`-Modul
- Test: Migrationen laufen von leer bis `head`

### Betrieb

- `Dockerfile`: multi-stage, non-root, `data/` als Volume
- `compose.yml`: App-Service, Volume-Mount, Port aus Umgebung
- CI grün (`quality`, `migrations`, `docker`)

## Abnahmekriterien

- [ ] `uv run pytest` grün, `uv run ruff check` und `uv run mypy src` sauber
- [ ] `docker compose up --build` startet, `/health` antwortet 200
- [ ] `Ctrl-C` beendet den Prozess ohne Traceback
- [ ] `alembic upgrade head` auf leerer DB läuft durch
- [ ] `alembic revision --autogenerate` erzeugt **keine** Änderung bei
      unverändertem Modellstand
- [ ] CI auf `main` grün
- [ ] Deploy per Tag auf Fuchs erfolgreich, Health-Check bestanden
- [ ] Fehlender Pflichtwert in `.env` führt zu Abbruch mit klarer Meldung

## Nicht in diesem Abschnitt

- Discord-Verbindung
- Authentifizierung, Sessions
- Frontend über die Fehlerseiten hinaus
- SSE-Terminal
- Fachliche Module

## Fußangeln

**Alembic-Autogenerate und Registry.** Autogenerate sieht nur importierte
Modelle. `env.py` muss die Discovery ausführen, bevor `target_metadata` gesetzt
wird — sonst kommt eine leere Migration ohne Fehlermeldung heraus. Das ist die
schwierigste Aufgabe dieses Abschnitts und sollte zuerst gelöst werden.

**`foreign_keys=ON` auch in Tests.** Fehlt das PRAGMA in der Test-Engine, laufen
Tests durch, die produktiv scheitern.

**Naming Convention von Anfang an.** Ohne sie erzeugt Alembic bei SQLite
unbenannte Constraints, die später nicht mehr geändert werden können.
Nachträglich einzuführen bedeutet, alle Migrationen neu zu schreiben.

**Uvicorn im Container beenden.** Ohne korrekte Signalweitergabe (kein
Shell-Form-`CMD`, `exec`-Form verwenden) hängt `docker compose down` zehn
Sekunden im Timeout.

**Erster CI-Lauf ist rot**, wenn `pyproject.toml` und Lockfile noch fehlen —
erwartbar, kein Grund zur Fehlersuche.
