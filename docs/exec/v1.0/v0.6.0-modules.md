# v0.6.0 — Weitere Module

## Ziel

Die verbleibenden Feature-Module nach dem Muster von `v0.5.0`. Vier Module,
die **je einen eigenen Minor-Tag** bekommen — dieser Abschnitt ist kein
einzelnes Release, sondern eine Reihe.

| Tag | Modul |
|---|---|
| `v0.6.0` | Violations |
| `v0.7.0` | Announcements |
| `v0.8.0` | Events |
| `v0.9.0` | Citations |

Der Härtungsabschnitt verschiebt sich entsprechend nach hinten.

## Voraussetzungen

- `v0.5.0` abgenommen und als Vorlage tauglich
- Für jedes Modul ein ausgefülltes Issue aus `module_proposal.yml`

## Gemeinsame Anforderungen

Für jedes der vier Module gilt unverändert:

- Aufbau nach `src/teabot/modules/README.md`
- Reihenfolge: Modell → Migration → Service mit Tests → Berechtigungen und
  Einstellungen → Adapter → Templates → Harness
- Kein Import aus einem anderen Modul
- Berechtigungen deklariert, Einstellungen deklariert
- Negative Tests für Berechtigung und Guild-Scoping
- Web-Aktionen nach Discord ausschließlich über das `BotGateway`

---

## Violations (`v0.6.0`)

Erfassung und Nachverfolgung von Regelverstößen: Verwarnungen, Stummschaltung,
Kick, Bann — mit Grund, Bearbeiter und Zeitpunkt.

Besonderheiten:

- Verstöße sind **historische Daten**. Sie werden nicht gelöscht, sondern
  allenfalls als aufgehoben markiert.
- Zeitlich befristete Maßnahmen brauchen einen Ablaufmechanismus. Entscheidung
  dokumentieren: Scheduler-Task oder Prüfung bei Zugriff. Bei einem Prozess ohne
  Scheduler ist Letzteres einfacher und ausreichend.
- Discords eigene Timeout-Funktion nutzen statt einer Rolle, wo möglich
- Der erste Kandidat für den Event Bus: ein Verstoß erzeugt einen Logeintrag,
  ohne dass `violations` das Logging-Modul importiert

Fußangel: Ein Nutzer kann den Server verlassen. Verstöße bleiben trotzdem
gültig — an der Discord-ID hängen, nicht an einem Mitgliedsobjekt.

---

## Announcements (`v0.7.0`)

Ankündigungen im Dashboard verfassen und in einen Kanal senden; Bearbeiten und
Löschen bereits gesendeter Nachrichten.

Besonderheiten:

- Reine Web→Discord-Richtung, also der Härtetest für das `BotGateway`
- Nachrichten-ID muss gespeichert werden, um später bearbeiten zu können
- Vorschau vor dem Senden
- Geplantes Senden bewusst **nicht** in v1.0 — das braucht einen Scheduler

Fußangel: Was passiert, wenn die Nachricht in Discord von Hand gelöscht wurde?
Bearbeiten muss diesen Fall abfangen, statt eine unbehandelte Exception zu
werfen. `allowed_mentions` restriktiv setzen, sonst pingt eine Ankündigung
versehentlich den ganzen Server.

---

## Events (`v0.8.0`)

Ankündigung und Verwaltung von Serverereignissen mit Teilnehmerliste.

Besonderheiten:

- Alle Zeitpunkte in UTC speichern, Anzeige in Ortszeit — hier fällt die
  UTC-Regel erstmals wirklich auf
- Teilnahme über Discord-Reaktion oder Button, gespiegelt in die Datenbank
- Discords „Scheduled Events" als Alternative prüfen und Entscheidung
  dokumentieren, statt beides halb zu bauen

Fußangel: Reaktionen können offline erfolgen. Beim Start ein Abgleich, sonst
divergieren Datenbank und Discord dauerhaft.

---

## Citations (`v0.9.0`)

Zitate sammeln, verwalten und abrufen.

Besonderheiten:

- Das einfachste Modul — gut geeignet, um das Muster ein letztes Mal ohne
  Sonderfälle durchzuspielen
- Volltextsuche über SQLite FTS5 prüfen; bei kleinen Datenmengen genügt `LIKE`
- Zufälliges Zitat per Command

Fußangel: Zitate enthalten Nutzertext. Ausgabe in Discord mit restriktiven
`allowed_mentions`, Ausgabe im Web ohne `|safe`.

---

## Abnahmekriterien je Modul

- [ ] Aufbau entspricht dem Slice-Vertrag
- [ ] Kein Import aus einem anderen Modul
- [ ] Service-Tests ohne Discord- und HTTP-Attrappen
- [ ] Negative Tests für Berechtigungen und Guild-Scoping
- [ ] Einstellungsseite ohne eigenen Template-Code entstanden
- [ ] Harness-Einträge für alle Zustände vorhanden
- [ ] Modul deaktivierbar, Commands dann inaktiv
- [ ] CodeRabbit meldet keine Schichtverletzung

## Nicht in diesem Abschnitt

- LLM-gestützte Bot-Antworten — eigenes Vorhaben nach v1.0
- Statistiken und Auswertungen über Module hinweg
- Scheduler für geplante Aktionen
- Mehrere Bot-Clients oder Versionen
